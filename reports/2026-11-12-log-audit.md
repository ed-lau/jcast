## 1. Summary

- **The log is 1.01 GB, 1,689 bytes per junction.** Of that:
  - **73% is sequence:**
    - each slice's nucleotides (61%);
    - its translated peptides (11%);
    - force-translated PTC peptides (1%).

    The peptides are in the output FASTA files. The nucleotides can be
    recomputed from the coordinates.
  - **24% is line decoration:** the time stamp, the level, and a
    `~module:…~function:…` suffix on every line. The suffix prints the
    module twice; the function name is never written.
- **Four in five junctions are logged in full and then skipped.**
  - The read-count filter runs after slicing, translation and the
    canonical lookup.
  - In this run, 471,821 of 599,644 junctions (79%) were skipped for low
    coverage. Every one of them logged its sequences first.
  - Skipped junctions cost as much time as translated ones (40 vs 42 ms
    each on chr15). **About 78% of this run's junction loop was spent on
    junctions it then discarded.**
- **The log does not contain:**
  - a summary of the run: fates per splice type, records per file, time
    taken;
  - the effective read-count threshold (PR 6 adds it);
  - a per-junction outcome in a form that can be filtered or joined.

  Today, finding why a junction or gene got its fate means searching
  1 GB of free text.

## 3. Filtering first

`_translate_one` ([main.py](../jcast/main.py)) runs these steps for
every junction:
1. trims it to the coding region;
2. reads its frames;
3. builds both slices (logging their nucleotides);
4. checks for masked bases;
5. looks up the canonical;
6. translates (logging the peptides);
7. **only then** applies the read-count and FDR filters.

The comment there says this order lets the canonical be written. Only the
canonical lookup is needed for that, not the slices or the translation.

Measured on chr15 ([timing.txt](log_audit/genome/timing.txt)):
- a junction skipped for low coverage takes 40 ms, against 42 ms for the
  others;
- at this run's share of skipped junctions (78.7%), they take 78% of the
  junction loop.

Applying the two filters first, then (with `-c`) looking up and writing
the canonical, would leave the skipped junctions almost no work and
almost nothing to log.

**What else changes:** a junction that is both low-count and masked
would report low coverage instead of masked bases. No such junction
exists on chr15 or in this run. Output files do not change.

## 4. Proposal

1. **Filter first.**
   - Apply the read-count and FDR filters before any other step. With
     `-c`, look up and write the canonical on that path.
   - It belongs with PR 6, which redefines the read-count filter. It also
     finishes PR 9's remaining item ("filter junctions before the
     canonical lookup").
   - **Expected:** the junction loop of an `-m` run 4–5× faster; the log
     about 70% smaller even before item 3.
2. **A per-junction table, `junctions.tsv`:** one row per junction, in
   run order, with:
   - type, rMATS id, gene id and symbol, read count;
   - fate;
   - the slices' frames, and the coding region;
   - the canonical's source and accession;
   - the files written to.

   Each row is about 110 bytes, about 66 MB for this run. It can be read
   straight into R or pandas.
3. **A small log:**
   - the run header: arguments, version, input paths with sizes and
     checksums, thresholds, model fit;
   - warnings and errors, including failed junctions (PR 7);
   - **an end-of-run summary:** fates per splice type, records per
     output file, failed junctions, time taken.

   Per-junction detail and sequences go to the log only with a new
   `--verbose` flag, at DEBUG level, as now.
4. **Line format:** keep the time stamp and level, and drop the
   `~module:…~function:…` suffix.
5. **Order:**
   - item 1 with PR 6;
   - items 2–4 as a new PR 16 after PR 8. It changes how
     `_translate_one` reports a junction's outcome, which PRs 7 and 8 also
     touch.

**Expected size for this run:**

| | Log | `junctions.tsv` |
|---|---|---|
| Now | 1.01 GB | – |
| Item 1 only | ≈ 0.3 GB | – |
| Items 1–4 | a few kB, plus warnings | ≈ 66 MB |
| Items 1–4 with `--verbose` | ≈ 0.25 GB | ≈ 66 MB |

## 5. Decisions requested

1. Filter by read count and FDR first, with PR 6 (recommended)?
2. Replace the per-junction log lines with `junctions.tsv` and an
   end-of-run summary, sequences only with `--verbose`, as PR 16
   (recommended)? Or keep one log line per junction (its fate) instead of
   a table?
3. Drop the `~module:…~function:…` suffix (recommended)?

## 6. Decisions (2026-11-12)

1. **Filter by read count and FDR first,** as part of PR 6. Approved.
2. **`junctions.tsv`, a small log with an end-of-run summary, and
   sequences only with `--verbose`.** Approved, as a new PR 16.
3. **Drop the `~module:…~function:…` suffix.** Approved, with PR 16.
